# LoadSight implementation status

Source workspace: `LoadSight/` in this repository. Installed copies use `LOADSIGHT_WORKSPACE` or `--workspace` to select a checkout.

The wrapper runs the local Swift package. Use `python3 scripts/loadsight.py validate|review|csv|air-review /absolute/project.json`, `python3 scripts/loadsight.py ingest /absolute/drawing.pdf`, or the structured `apply` interface documented in [project-edits.md](project-edits.md). No network provider or Ops database is called. CLI project inputs are self-contained JSON exports, not `.loadsight` package directories.

## Implemented and verified at model/build level

- Lossless version-1 project JSON; original PDF/image retention, source fingerprints, PDF text/page coordinates, local Vision OCR and orientation normalization. Native packages and JSON retain drawings. Symbol interpretation and title-block identity still require review.
- Native Mac/iOS document targets; drawing viewer, counts with duplicate-view evidence, lifecycle tags, per-region calibration/check, measured routes and durable undo. Geometry-derived quantity edits are protected. Drawing UI/touch acceptance remains unverified; selected iOS26.2 calculation/save/reopen workflows passed in the workspace runtime notes.
- Native item quantity/scope review, written allowances, cost entry and commercial/proposal details. Unknown prices remain unknown; material-only waste and markup-on-cost are deterministic. Review gates withhold incomplete selling prices.
- RFI create/edit, sourced resolution, reopening and history. Native QA checklist records reviewer evidence and binds new reviews to semantic project state. New final QA requires an independent recorded name and current preceding checks. Identity is not authenticated.
- Supporting attachments retain exact bytes, SHA-256 and provenance, deduplicating content with optional RFI links. Current storage embeds attachments in project JSON, limited to 64 MB per file.
- Structured edits: changeorder.create, changeorder.revise, rfi.create, rfi.edit, rfi.resolve, rfi.reopen, commercial.update, proposal.update, item.review, qa.review, attachment.add, aircondition.create, aircondition.derive, airprocess.create, assembly.create, room.transmission.create, room.transmission.revise. The engine writes a new file, preserving existing paths and input originals. Consult project-edits.md for exact required fields and evidence requirements.
- Selected RFI DOCX export from the shared native engine, including current question/source/impact/answer, linked items, attachment references and before/after workflow history. Native and structured RFI edits now record recipient, sender, request date, response deadline and suggested resolution, with optional blank values, real-calendar validation, history and backward-compatible preservation when omitted. Missing routing/date fields remain Not recorded. Export does not send, resolve, approve or mutate the project, and referenced attachment files are not embedded. Use `python3 scripts/loadsight.py rfi-docx /absolute/project.json --rfi-id RFI-ID --output /absolute/new.docx`. The wrapper refuses existing output paths and symlinks. See [rfi-word-export.md](rfi-word-export.md).
- CSV, native three-sheet takeoff XLSX snapshots, and native draft proposal PDF with recorded quantities, commercial terms, source register and RFIs. Draft PDFs never issue a final selling price. The direct Swift CLI supports `draft-pdf project.json new.pdf`; the Python wrapper currently exposes the commands listed above.
- Pressure-aware moist-air states from dry bulb plus RH, thermodynamic wet bulb or dew/frost point; saved records preserve the original humidity mode/value and derived-RH consistency, with input classifications, provenance and assumptions; native air mixing and air-side cooling-coil load calculations from saved conditions and actual inlet CFM. The `air-review` command returns recomputed states, process results, assumptions and equation traces. Saving conditions/processes reopens QA. A saved mixing process can produce a reusable calculated condition through aircondition.derive; fingerprints bind all upstream records, and graph validation rejects stale values, missing references and cycles. These are bounded engineering worksheets, not completed building loads, manufacturer capacity selections, or fog models. Cooling output now includes supplemental ADP/process-line intersections at site pressure, with temperature/humidity/enthalpy bypass factors, residuals and explicit multiple-root/tangency/unresolved statuses. It does not select a physical coil from ambiguous candidates. See [air-processes.md](air-processes.md).
- Native envelope assembly worksheet records complete resistance layers within independent area-weighted paths, with per-input source/classification, author, surface-film basis, assumptions and equation traces. Supported construction labels are wood framed and homogeneous layers. `assembly.create` uses the shared SDK and `envelope-review` recomputes saved results. Missing sources, unresolved RFIs, invalid fractions/resistances and unsupported methods fail validation. No material/film defaults or metal-frame/ground-coupling model; assemblies now feed the partial room opaque-transmission worksheet. See [envelope-assemblies.md](envelope-assemblies.md).
- Native room transmission cases link sourced design temperatures and gross/opening surface areas to saved assemblies. Named opening deductions, per-surface traces, separate outward loss/inward gain and signed net balance are recomputed by the SDK. `room.transmission.create` saves and reopens QA; `room-review` returns room inputs/results and referenced assembly sources. Optional sourced whole-product U-factors now calculate opening transmission separately, with combined envelope subtotals withheld if any listed opening is unrated. New records use method v2; legacy v1 records remain readable without opening ratings. This is above-grade steady-state transfer only; ground, infiltration/ventilation, solar and other complete-load components remain unmodeled, not zero. Room revisions now preserve stable identity, reason/author/date, before/after inputs and assembly-basis snapshots. Edit fingerprints reject stale room/catalog revisions; native history supports before/after review. History is a consistency-checked local record, not authenticated approval. See [room-transmission.md](room-transmission.md).
- Elementary load/air/ventilation/hydronic/gas arithmetic and duct geometry with traces. These are not complete design methods or code determinations.

- Change-order draft creation and recomputed signed USD cost review, sourced original/proposed quantity ledger, explicit markup basis, unknown totals, RFI links and QA reopening. Use `change-review` and see [change-orders.md](change-orders.md). Native CO creation and saved-record review now use that shared model, with typed numeric validation and unsaved-change protection. CO DOCX export includes quantity/cost tables, source evidence and draft terms; see [change-order-word-export.md](change-order-word-export.md). Native and plugin corrections preserve full snapshots, creator metadata, authored reasons and stale-edit tokens; native history exposes before/after records, and Word includes changed fields. Authenticated approval remains pending.

## Still outstanding

Read `BUILD_STATUS.md` in the source workspace for current test/build evidence and the full scope. Autonomous geometry/symbol extraction, full load/psychrometric/distribution methods, adopted-code research, complete equipment selection, live pricing-workbook formulas, authenticated approval/final release comparison, priced alternates, local REST, direct GunnAire Ops publishing and physical-device/visual acceptance remain unfinished. Skill definitions describe the requested product; their presence does not prove implementation.

Use the actual supplied drawings for new conclusions. The dental JSON is recovered prior-review data, not an independent current drawing verification. Text recognition confidence is not engineering confidence. Preserve mechanical scope and HVAC interfaces; plumbing and electrical trade takeoffs remain excluded unless expressly included.

When a command fails, report the result and continue supported local work. Never claim failed arithmetic or review succeeded. Do not invent reviewer decisions or field verification. Do not send proposals, contact suppliers, place orders or mutate accounting based on plugin availability.

Recorded customer/job context is available through `ops-review` and `ops.context.update`; see `ops-project-context.md`. These are local snapshots with authored history, not authenticated billing actions.

Catalog material snapshots are available through `catalog-review` and `catalog.material.update`. See [catalog-material-mapping.md](catalog-material-mapping.md) for exact fields, explicit USD/unit evidence, unknown costs, history, removal and stale-edit protection. No live catalog fetch or accounting publication is performed.

`xlsx project.json --output new-workbook.xlsx` exports the native five-tab workbook: Takeoff, RFIs, Review, Material costs and Catalog history. It retains current/stale/removed/unmapped cost states, blank unknown costs, source identities, purchasing-unit conversion and full before/after field history. Values are fixed export snapshots, not a live catalog or recalculating pricebook. Existing paths and symlinks are rejected.

The asynchronous local SDK service, bounded progress operations and Combine adapter are available to host apps. See [sdk-service.md](sdk-service.md) for methods, cancellation, the compiled host example and explicit pipeline limitations.

Mechanical text-occurrence extraction and source-validated RFI handoff are available through `extract-text`, `extract-review` and `text.rfi.create`. See [mechanical-text-extraction.md](mechanical-text-extraction.md). These are unreviewed text occurrences, not complete schedule/geometry extraction or physical quantities.

Mapped equipment schedule row extraction is available through `schedule-text`, `schedule-review`, the SDK and native Schedules workspace. See [equipment-schedules.md](equipment-schedules.md) for the explicit source/column contract and unreviewed-row limits.

Native schedule maps now support authored creation/revision/removal with durable package/JSON history, stale-edit protection and QA reopening. `schedule-map-review`, `schedule-saved`, `schedule.map.save` and `schedule.map.remove` expose the same models through the plugin; see [equipment-schedules.md](equipment-schedules.md). Saving a column map does not approve extracted equipment.

Schedule extraction now includes separate scalar numeric interpretations for explicit supported units, with missing/ambiguous values held unresolved. Native review shows the value and conversion basis beside literal evidence. See [equipment-schedules.md](equipment-schedules.md); equipment plausibility, broader unit conventions and approved design-input association remain unfinished.

Conditional schedule consistency screening now reports missing/unresolved coordination fields, comparable sensible/total and outdoor/total ordering conflicts, and zero-capacity review prompts. Partial or low-confidence evidence withholds comparisons. Findings remain conditional and do not approve equipment or design values. See [equipment-schedules.md](equipment-schedules.md).

`schedule.rfi.create` and the native schedule finding action create an unanswered local RFI plus exact linked row/finding evidence snapshot, after current-source validation. No external message is sent. See [equipment-schedules.md](equipment-schedules.md).

Explicit two/three-part decimal schedule dimensions can now be interpreted in metres in source order through dimensionReview and native cell review. Unknown unit/axis meaning and unsupported notation remain unconfirmed; no area/volume/quantity is inferred. See [equipment-schedules.md](equipment-schedules.md).

Source-defined MBH/Btu/ton and US/Imperial GPM conventions now require compatible literal units and recorded legend/specification evidence. Native map editing, retained history and extracted row snapshots share this contract; see [equipment-schedules.md](equipment-schedules.md).

Automatic header/tag-alignment schedule discovery now proposes source-bound editable maps through the native workspace, asynchronous SDK and read-only `schedule-discover` / `schedule-discover-review` commands. Unknown/duplicate headers remain unmapped; unsupported layouts require manual mapping. See [equipment-schedules.md](equipment-schedules.md).
