# OAuth Callback Routing

QuickBooks uses the provider-registered HTTPS callback bridge. Google uses the
native iOS OAuth client directly with PKCE and the reversed Google client-ID
scheme; it must not be routed through the QuickBooks bridge.

## App Expectations

QuickBooks values should be set as:

- `QB_REDIRECT_URI=https://gunnaire.com/wp-json/ga/v1/qbo/oauth/callback`
- `QB_CALLBACK_SCHEME=gunnaireops`

For Google, configure the iOS OAuth client values generated by Google Cloud:

- `GOOGLE_CLIENT_ID=<client>.apps.googleusercontent.com`
- `GOOGLE_REVERSED_CLIENT_ID=com.googleusercontent.apps.<client>`
- `GOOGLE_CALLBACK_SCHEME=$(GOOGLE_REVERSED_CLIENT_ID)`
- `GOOGLE_REDIRECT_URI=$(GOOGLE_REVERSED_CLIENT_ID):/oauth2redirect`

## Required Server Behavior

After the QuickBooks web callback endpoint receives OAuth params, redirect to
the app scheme:

- QuickBooks:
  - From: `/wp-json/ga/v1/qbo/oauth/callback?code=...&state=...&realmId=...`
  - To: `gunnaireops://oauth/qbo?code=...&state=...&realmId=...`

## Notes

- Preserve `code` and `state` exactly.
- Preserve `realmId` for QuickBooks.
- Use an HTTP 302/307 redirect.
- If callback contains `error` and `error_description`, forward those query params to the app scheme too.
- Google authorization returns directly to the reversed client-ID URL scheme.
  The app verifies OAuth state, uses PKCE, and exchanges the code without a
  client secret. Never place a Google client secret in the app or an xcconfig.
