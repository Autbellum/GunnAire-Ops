# Original humidity input modes

The air-state worksheet now accepts dry bulb and absolute station pressure with one humidity input: relative humidity, thermodynamic wet bulb, or dew/frost point. It retains that source mode/value alongside derived RH. This supports a supplied design-condition basis without requiring the user to replace it with a separately calculated RH.

## Equations and references

The conversion equations follow the retained [PsychroLib primary implementation and API references](https://psychrometrics.github.io/psychrolib/api_docs.html#psychrolib.GetHumRatioFromTWetBulb), including ASHRAE 2017 Fundamentals chapter 1 wet-bulb balances (equations 33/35) and the saturation-pressure RH relationship. The retained Python source, SHA-256, license and property basis remain documented in Psychrometric-method.md. No instrument correction, design-weather selection or current-code determination is implied.

- RH input: fraction in the SDK/API; percent in native UI.
- Dew/frost point: Pv = Pws(Tdew), then RH = Pv/Pws(Tdry). Below the triple point the existing saturation method uses ice.
- Wet bulb at/above 0 °C: W = [(2501−2.326Twb)Wsat−1.006(Tdb−Twb)] / [2501+1.86Tdb−4.186Twb].
- Wet bulb below 0 °C: W = [(2830−0.24Twb)Wsat−1.006(Tdb−Twb)] / [2830+1.86Tdb−2.1Twb].
- Wsat = 0.621945 Pws(Twb)/(P−Pws(Twb)); reconstruct RH from W and site pressure with the same property method.

All temperatures in these equations/API fields are °C. Native UI displays/accepts °F and converts explicitly; absolute pressure remains psia in UI, Pa in API. The native input selector clears its numeric humidity field when changing mode to prevent a percent value from being silently reinterpreted as a temperature.

## Bounds and phase handling

Existing dry-bulb/pressure domain applies: −100 to 80 °C dry bulb, 20–120 kPa, and dry-bulb saturation pressure below total pressure. Wet bulb and dew/frost point must be finite, at least −100 °C and no warmer than dry bulb. Negative implied W is rejected; only numerical negativity up to 1e−12 kg/kg is rounded to zero. There is no arbitrary minimum humidity clamp. Saturation input returns RH=1.

The supplied wet-bulb value fixes its water/ice balance branch. It is retained as the reported thermodynamic wet bulb even if a reverse solve from RH encounters another branch near freezing. If the reverse result is unavailable or differs by more than 0.002 °C, an explicit note explains the retained input branch. This does not apply instrument-specific corrections to observed psychrometer data.

## Storage, traces and compatibility

`AirConditionRecord.humidityInput` is an optional `{kind,value}` object. Kinds: `relativeHumidity`, `wetBulbC`, `dewPointC`. Records newly saved by any input mode retain the object. Legacy records without it remain RH-based. The stored derived `relativeHumidity` must be finite and agree with recomputation within 1e−10. A mismatch rejects portable/native validation instead of silently choosing one value. The original source, author, classifications and assumptions remain retained, and saving reopens QA.

The existing `saveAirCondition(...relativeHumidity:...)` SDK signature delegates to the new humidity-input overload. The plugin's `aircondition.create` accepts either its original `relativeHumidity` field or the new `humidityInput` object, never both. Nested keys must be exactly kind/value, with a valid kind and numeric finite value; strings, unknown kinds, extra nested fields and conflicting input forms are rejected. Other required source/classification fields are unchanged.

Native results/saved records show the original input basis and a conversion-equation disclosure. `air-review` returns `inputTrace` with equation, substituted values, result, units and assumptions for each saved condition. A derived RH is not relabeled as the original measurement.

## Evidence and remaining scope

82 XCTest tests pass. Four new tests include 56 cases generated by the retained upstream Python implementation: 48 combinations across −30/−5/5/25/40/60 °C, 65/101.325 kPa, RH-derived seed states at 30/80%, and both temperature input modes; plus eight wet-bulb/dew-point cases at −0.001, 0, 0.01 and 0.010001 °C. Expected outputs are calculated by the reference from each actual supplied input, not compared with a rounded seed RH. Tests also cover saturation, impossible combinations, nonfinite values, original-value native package persistence, legacy RH compatibility, derived-RH tampering, exclusive API choices and strict types.

Mac and iOS builds pass. The installed plugin verification includes both new modes and trace output, preserving source files and rejecting overwrite. UI/touch interaction remains unverified due to the previously observed unavailable computer-use connection. Published/field benchmarks, instrument corrections, design-weather/percentile/coincidence validation, full room/system loads, equipment selection and complete process-network revision/flow workflows remain unfinished. Reusable mixing outputs are now described in Air-network-method.md. This is source-input and calculation support, not complete project engineering.
