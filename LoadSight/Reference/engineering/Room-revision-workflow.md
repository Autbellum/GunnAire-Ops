# Room transmission revisions

The room calculation method remains v2; this adds editing/persistence behavior. Native and structured revision paths share `reviseRoomTransmission`. Inputs undergo the existing room/assembly/condition checks before publication. A revision retains stable ID, writes a new author/date and reason, preserves unknown room-level extensions, and replaces explicitly supplied surface/opening inputs. Full prior raw inputs remain in the history snapshot. QA reopens.

Optimistic edit fingerprints cover sorted-key JSON of the full room, its latest revision identity and the current entire assembly catalog. The broad catalog guard prevents changes to newly selected assemblies from slipping through an older editor baseline. Any catalog change requires reload/review; unrelated QA or other room edits do not. Tokens are change detectors, not signatures or authorization. The native form obtains current inputs when loading after a discard confirmation, clears the previous author's name, retains draft text on a stale-save error, and clears calculation previews on draft/project changes.

History entries contain before/after full room inputs and the union of their referenced assembly records at revision time. room-review includes recomputed beforeResult/afterResult values and traces. Historical results are recomputed using that saved basis and remain stable when live assemblies subsequently change. This is a revision-time basis, not a reconstruction of unknown earlier assembly states. History validates distinct IDs, author/date, same room identity, sequential before/after continuity, current-room agreement and both snapshots' calculation against their saved assemblies. It is a local consistency record, not authenticated signoff or tamper-proof storage.

Tests: seven RoomRevisionTests cover stable IDs/count, QA reopening, before/after analytical results, stale/no-op revision tokens, invalid-request atomicity, assembly-change token invalidation, QA-change token stability, historical-basis preservation, broken chain/current-state rejection, unknown input preservation, native package roundtrip and strict structured requests. Native visual/touch acceptance remains separate.
