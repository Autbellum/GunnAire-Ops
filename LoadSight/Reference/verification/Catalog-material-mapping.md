# Catalog material cost mapping

LoadSight can now record an explicit material purchase-cost mapping from the Ops local catalog. The Takeoff row's **Catalog cost** action opens a source picker, purchasing-unit conversion, USD confirmation, compatibility/source evidence, recorder and reason. Applying changes material cost only. Quantity, drawing evidence, labor, subcontract/other costs, material waste and the existing combined price/labor reference remain unchanged. QA reopens. This does not select equipment, order materials, publish accounting records or approve a bid.

## Source and cost contract

The Ops host supplies only unambiguous UUIDs for approved Inventory/NonInventory records, excluding archived sync records and invalid snapshots. Service, group/bundle and category records are not treated as purchased materials. Records are read from the existing local catalog; no network lookup or provider update is performed. The source string records the host's configured context, not independently verified provider ownership. The snapshot retains local item UUID, name, SKU, supplier name/part, purchase cost and catalog timestamp. It intentionally does not substitute the catalog selling price.

The existing Ops model does not establish a purchasing unit or currency for this bridge. The estimator must explicitly confirm USD, identify the purchasing unit and enter **catalog units per one takeoff unit**, with written conversion and compatibility evidence. For example, a $50 five-foot length mapped at 0.2 purchased lengths per LF produces $10 material cost per LF; existing quantity and waste calculations then apply separately. The factor must be finite and positive; unsupported currency, overflow and missing evidence are rejected. This is a recorded estimator assertion, not automatic dimensional analysis or supplier quote verification.

Unknown purchase cost remains null and replaces a previously entered number with unknown when applied. A confirmed zero remains zero. Source snapshots are frozen when the editor opens and on save. A later live catalog edit does not silently update an estimate; the saved snapshot remains available for inspection or explicit reuse. Quote expiration/lead-time policies and supplier refresh are not implemented by this mapping.

## History, edits and persistence

Every application, revision and removal records item identity, author, timestamp, reason, full before/after mapping snapshots and before/after material costs. Import validates unique revisions, the per-item mapping chain, dates, metadata and converted after-cost. Removing a mapping preserves current material cost and history; the manual cost basis must then be reviewed. Mapped rows cannot be deleted without first removing the link. These are local consistency checks, not authenticated or tamper-proof approval.

The editor fingerprint covers the current takeoff row and latest mapping revision. Concurrent/manual item edits reject an old form. An existing mapping becomes stale for pricing review when material cost, unit, description or lifecycle differs from its recorded basis. Unrelated project edits do not invalidate this item's form. Missing price/labor references remain existing review blockers; a material snapshot does not establish a labor basis.

Native package and portable JSON retain source snapshots and history. Ops draft recovery uses the same complete project state. The native sheet guards unsaved dismissal and displays save errors. The current USD confirmation must be made each time a mapping is applied.
