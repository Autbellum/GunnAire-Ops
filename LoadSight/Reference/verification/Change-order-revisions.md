# Change order revisions

Implemented stable-identity draft corrections in the shared Core model, native app and plugin. `changeorder.revise` requires a complete draft, record ID, expected edit fingerprint, editor and reason. Current CO inputs and latest revision identity determine the token. A stale token fails without mutation. Same-values revisions still create a new token; unrelated CO/QA changes do not invalidate the record token.

The CO creator, project snapshot, creation time and draft status remain unchanged. Each revision stores its own author/time/reason and full raw before/after snapshots. QA reopens. History validation checks unique IDs, valid records and dates, unchanged creation metadata/status, sequential snapshot agreement and current-record agreement. No authenticated approval or tamper-proof storage is claimed. New RFI links must exist; existing historical links may remain after their source RFI is removed.

Native Revise draft loads all supplied numbers, sources, quantities and narratives. It starts with an empty editor field and requests a reason. Failed/stale saves preserve the typed draft. History buttons open full before/after record views. Word export identifies the latest revision and includes a changed-field appendix with before/after source evidence, quantity/cost ledgers when changed, and totals. Complete snapshots remain in the project.
